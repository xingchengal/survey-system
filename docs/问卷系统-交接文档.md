1. `job_kill` **不会**杀掉 maven fork 出来的 java（它只结束包装进程，java 仍占着端口）；
2. **查端口与杀进程必须在同一条命令里完成**（拿上一条命令查到的 PID 去杀，那个 PID 可能已经变成别的实例）：
   ```powershell
   $l=(netstat -ano | Select-String 'LISTENING' | Where-Object { $_.Line -match ':8081\s' } | Select-Object -First 1)
   if($l){ Stop-Process -Id (($l.Line.Trim() -split '\s+')[-1]) -Force }
   ```
   ★ 沙箱里 **`Get-NetTCPConnection -State Listen` 返回空**（连几十个监听端口都查不出来），定位端口一律用 `netstat -ano`。
   ★ 只按端口定位，**别用 `Stop-Process -Name java`**（会误杀你 8080 的实例）。
3. **"实例活着"≠"跑的是新 class"**：实例若起得比最后一次改动早，你就是在测旧代码。
   涉及路由/端点的改动，先用一个"只有新代码才有"的探针验收（如"已删端点应 404"），别只看源码或进程活着。

> ★ 起服务前先 `clean compile`：你的 VSCode/IDEA 一直开着，它的 Java 扩展会在后台编译 `target/classes`，
> 与我的改动不同步；而 Maven 只看时间戳会报 "Nothing to compile" 直接跑 →
> 会在"类文件都在"的情况下吃到 `NoClassDefFoundError`（实测追了半小时）。

**要一枚有效的 admin token 做验证时**：别去猜口令，也别反射塞密钥签票 ——
用注册接口造一个普通账号（拿到真实 PBKDF2 哈希），再 `UPDATE t_user SET role='admin'` 提权，**跑完删掉**。

## 三、必须遵守的 18 条约定（改代码前先看）

1. **业务失败一律 `throw new BizException(原因)`**，不要 `return "错误文案"` / `return null`。
   前端只看 HTTP 状态码（2xx 成功 / 非 2xx 读 `message`），`api/http.js` 里**没有任何中文字符串比对**。
   ★ 用 `BizException` 而不是 `RuntimeException` 的原因：前者**不写** `t_error_log`，否则"输错密码""无权限"会把异常日志刷满。
2. **管理端点挂 `@RequireAdmin`**（类级或方法级），不要手写 `if (!"admin".equals(role))`。
   归属校验仍显式写在 Service/Controller 里 —— 注解只管角色那一半。
3. **Controller 不注入 Mapper、不写 `@Transactional`**；业务与事务放 Service。
4. **状态/题型判断用枚举**（`SurveyStatus.isPublished(x)`、`QuestionType.hasOptions(x)`），
   不要再写 `status == 1`、`type == 1 || type == 2`。
5. **改完后端要重启**（项目**没有** `spring-boot-devtools`）；前端 Vite dev 会热更新。
6. **角色判断一律 `Role.isAdmin(role)`**；**归属校验一律 `OwnershipGuard`**
   （`requireOwnerOrAdmin` / `requireVisible` / `requireNotInRecycleBin`），不要手写 `survey.getUserId().equals(userId)`。
7. **新的入参校验用 DTO + `@Valid`**（模板见 `com.survey.dto`），失败由 `GlobalExceptionHandler` 统一翻成 400；
   老的 `if (...) throw new BizException(...)` 仍有效 —— 迁移时**迁一个删一处**，别让两套规则并存。
   ★ 系统级故障抛 `RuntimeException`（→ 500 + 固定文案）；业务失败抛 `BizException`（→ 400 + 你的文案，且不写异常日志）。
8. **别把 `survey-backend/.mvn/` 加回 `.gitignore`**：`mvnw` / `mvnw.cmd` 是入库的，必须配合
   `.mvn/wrapper/maven-wrapper.properties`（里面有 `distributionType=only-script` 与发行版地址）。
   拿掉它 `mvnw.cmd` 直接崩。另外 `mvnw` 在 git 索引里必须带**可执行位（100755）**，否则 Linux/macOS 上 clone 后 `./mvnw` 会 Permission denied（Windows 上看不出来）。
9. **`@Transactional` 标在"会被同类内部调用"的方法上等于没写**：Spring 事务基于 AOP 代理，`this.xxx()` 不经过代理。
   后果是多表删/插各自 autocommit → **半删/半成品数据**。
   规则：**薄包装方法自己也要标 `@Transactional`**，或在外层编排方法里用 `TransactionTemplate` 显式开事务。
   ★ 尤其**别给包含外部 HTTP 调用的方法加 `@Transactional`** —— AI 那条最长 120 秒，会把数据库连接占死。
10. **任何"长度/条数上限"都必须与它落库的地方对账**：**Java 校验上限 > 数据库列宽**时，
    超长会通过校验、再被 MySQL 拒绝，用户看到 **500** 而不是 400。
    8 个文本上限集中在 `common/TextLimits`，**它的值必须等于 `information_schema` 里的列宽**；
    要放宽就**先 `ALTER TABLE` 再改 TextLimits**，别只改 Java 那一侧。
    同理 `PageParams.MAX_PAGE_SIZE`(100)、`AnswerController` 的导出上限（答卷 5000 / **明细行数 50000**，真正的口径是后者）、
    `AnswerDetailMapper.findTextAnswers` 的 `LIMIT 2000` 都是"防护上限"，改之前先想清楚它在挡什么
    （例如给 `findBySurveyId` 加 LIMIT 会让导出**静默截断** —— 特意没加）。
    ★ 头像那条例外要说清楚：`AvatarValidator.MAX_CHARS`(3MB) 是**字符串长度**的第一道闸，
    **真实生效上限是解码后 2MB**（`MAX_BYTES`），前端也按 2MB 对齐。
11. **模糊搜索参数一律先过 `SqlLikeEscaper.escape()`**：否则用户输入一个 `%` 就等于"匹配所有行"。
    ★ 只转义**用户输入**；演示数据那种固定字面前缀（`findByUsernamePrefix("demo_user")`）不要转。
12. ★★ **验证编译必须用 `mvnw -o clean compile`，不要只用 `compile`**：
    IDEA 开着时会做**容错编译**（ECJ），把"有编译错误但能生成"的 class 写进 `target/classes`；
    而 Maven 增量编译看到 class 比源码新就跳过 —— 于是报 **BUILD SUCCESS**，
    运行时却抛 `java.lang.Error: Unresolved compilation problem`（HTTP 500）。实测因此白跑过两轮验证。
13. ★★ **停临时实例的可靠流程**：`job_kill` → **同一条命令里按端口找 PID 杀** → 起实例 →
    **先用"只有新代码才有"的探针确认** → 再跑正式验证。（详见 §二的三条）
14. **"能不能做"的不变量都在 Service 层**，不要只写在 Controller 里：
    `OwnershipGuard.*`、`AnswerService.submit` 的守卫、`UserService.deleteUser` 的删除保护。
    新增入口时先想"这个不变量有没有统一入口可用"。
15. ★★ **删端点 / 改路径变量之前，先想"这个 URL 会被谁接住"**：
    - 删掉字面量端点（如 `/survey/list`）后，同一 URL 会落进 `GET /api/survey/{id}`，
      而 `@PathVariable Integer` 遇到非数字**在进入方法体之前**就抛错 → 客户端拿到文案指向不存在参数的 400。
      现在的做法：`getOne` 的路径变量改成 `String`，先查 `SurveyController.REMOVED_LITERAL_PATHS` → **404 +「该端点已下线…」**，
      非数字再给 400。**以后删单词式端点，把名字加进那张表。**
    - **别用 `ResponseStatusException` 而不加处理器**：它继承 `RuntimeException`，会被 500 兜底吃掉
      （实测 404 变 500 且写了 3 条异常日志）。现在有专门的 `@ExceptionHandler(ResponseStatusException.class)`：用它自带的状态码 + 文案，**4xx 不写日志**。
    - 删完端点的验收口径：**HTTP 实测** —— 已删 URL 必须 404/405（文案不误导）、保留端点全部 200、
      `t_error_log` 不增长、`SurveyControllerRoutingTest` 变绿。
16. **代码注释里引用文档，要写仓库内的相对路径**（`docs/xxx.md`），且被引用的文档**必须随仓库入库**，
    否则别人 clone 后注释就是断链。`问卷系统-修改记录.md` 这类过程文档**有意不入库**，注释里别"详见"指向它们。
    当前入库的见 §六。
17. ★★ **"前端零调用"是删端点的**必要**条件，不是**充分**条件**：删之前多问一句 ——
    **这个端点是不是某条业务能力的唯一写入路径？** 判据是"**有没有替代者**"，比"有没有调用者"更关键。
    - 反例（删错了、已恢复）：`POST /api/answer/submit/{surveyId}` 前端零调用，
      但它是**唯一**能把答题人身份写进 `t_answer.user_id` 的路径（`submit-share` 传的 `userId` 恒为 `null`）。
      删掉它那一列就成了死列，且「答卷防重 / 我的答题历史 / 实名问卷」的实现路径被一起堵死。
    - ★ 同时**别说乐观话**：恢复端点 ≠ 功能就绪。（当时注释写得像"防重已就绪"，其实守卫是后来才写的。）
    - ★★ **注释卫生三条硬规矩**（本项目最大的注释隐患是"改造前/改前"叙事混进现状断言）：
      ① **"过去"必须显式标时态**（"原来是…"），别让读者以为在说现状；
      ② **凡是能验的事实（请求数 / 行号 / 类名 / 上限 / 后端状态码）都要写得出处**，改动代码时**顺手核一遍同一段注释**；
      ③ **不要指向"文件顶部 ⚠️ 说明"这类相对锚点**（段落一改就断链）—— 要么就地写清结论，要么写章节标题。
18. ★★ **新增测试类不需要改 CI —— 但要确认它真的被跑到了**：
    测试由 **`./mvnw -B test` 默认全跑**；唯一需要真实 MySQL 的 `SurveyBackendApplicationTests`
    由 `survey-backend/pom.xml` 的 surefire `<excludes>` 排除。
    所以**新增测试类只需写进 `src/test`**，`pom.xml` 与 `ci.yml` 都不用动。
    ★ 历史教训：`ci.yml` 曾用 `-Dtest=类名,...` 的手工列表，**落后 3 轮**都没人发现，等于那道闸门是空的。

## 四、代码地图：改哪之前先认哪个

### 唯一口径类（同一件事只允许有一个出处）

| 文件 | 作用 |
|---|---|
| `common/BizException.java` | 业务失败统一抛它 → 400 + `{success:false,code,message}`，且**不写异常日志** |
| `common/Role.java` | **角色常量唯一口径**（`ADMIN`/`USER` + `isAdmin`，容忍 null） |
| `common/OwnershipGuard.java` | **问卷归属校验唯一口径**（`requireOwnerOrAdmin` / `requireVisible` / `requireNotInRecycleBin`） |
| `common/SurveyStatus.java` / `common/QuestionType.java` | 状态枚举（**NULL 视为草稿**）/ 题型枚举 + `hasOptions()` |
| `common/TextLimits.java` | **文本上限唯一口径**，值必须等于数据库列宽 |
| `common/SqlLikeEscaper.java` | LIKE 通配符转义（用户输入才转） |
| `common/AvatarValidator.java` | **头像校验唯一口径**：data URL 形式 → png/jpeg/gif 白名单 → base64 解码 → 魔数与声明一致；`MAX_CHARS`(3MB) / `MAX_BYTES`(**2MB，真实上限**) |
| `util/WebUtils.java` | `getClientIp()`（日志）/ `getConnectionIp()`（限流，**不看请求头**）/ `writeJsonError()`（两个 Filter 共用） |
| `util/JwtUtil.java` | 签发与校验；有效期**只有 `application.yaml` 一个来源**（有效期 12h）；`isIssuedAtOrAfter` 的语义是 **iat 严格晚于 cutoff** |
| `config/RateLimitInterceptor.java` | 限流 9 条 → 429。★ 计数键用**真实连接 IP**（防 `X-Forwarded-For` 伪造绕过） |
| `config/GlobalExceptionHandler.java` | 全部异常 → 统一 JSON；4xx 不写异常日志，5xx 照常记 |
| `filter/JwtAuthFilter.java` | 第一道门（`@Order(1)`，**排在 `RequestSizeFilter` 之后**）：白名单 10 分支/11 端点、注入 `X-User-Id`/`X-User-Role`、**查库判账号是否有效**并比对 `token_valid_after` |
| `filter/DocAccessFilter.java` | 文档路径（Knife4j）单独限管理员，与 API 拦截职责分离 |

### 关键不变量与实现点

| 项 | 要点 |
|---|---|
| **`UserMapper` 的软删除口径** | ★ 本接口里**每一个查用户的 SQL 都带 `deleted_at IS NULL`**，只有 3 个故意不过滤（`findByIdIncludeDeleted` / `findByUsernameIncludeDeleted` / `findByUsernamePrefix`，各自 javadoc 写了为什么）。**新增任何 `FROM t_user` 查询前先读那条类注释** —— 漏一处 = 已注销账号还能用 |
| 账号注销 | 只写 `t_user.deleted_at`（不级联删任何东西）；用户名继续被占用（防抢注）；注销需密码；`restoreUser` 同时写 `token_valid_after` ⇒ **恢复后必须重新登录** |
| `token_valid_after` | 写入点两个：`UserService.updatePassword`、`restoreUser`（都截到秒）；比较口径**严格 iat > cutoff**（同秒一律拒，否则旧票跑不掉） |
| 答卷防重 | 登录用户按 `survey_id + user_id` 查重 → 400；**匿名侧有意不查**（NAT 误伤）。并发缺口与**正确修法**见《待解决问题》A1 |
| 跳转 `nextQuestionId` | 存的是**真 `question.id`**（不是 1 基序号）；保存时校验目标属于本问卷；复制问卷做跨问卷映射 |
| 多选题口径 | **一选项一行**（每题最多 50 行），单选/填空严格一行。★ 要改这个口径，必须同时改统计页的 `GROUP BY content`、演示数据与历史数据，否则图表失真 |
| 发布/更新状态机 | 回收站问卷不能编辑/发布/收答卷/设模板；已结束问卷要**先延长截止时间**才能重新发布；`SurveyMapper.update` 的 SQL **不含** `status`/`share_code`（把不变量搬进了 SQL） |
| 分享码 | **服务端独占**：`/survey/update` 传 `shareCode` 会被忽略，`/publish/{id}` 才生成 |
| 展示层重复 | `UserProfile.vue` 与 `AdminProfile.vue` 是**一份复制品**（模板/data/方法/scoped 样式几乎逐行相同），**改一边必须同步另一边** |

## 五、环境与工具坑（都是实测踩过的）

| 坑 | 说明 |
|---|---|
| **文件沙箱** | 只能写工作区 `C:\Users\1\Desktop\dsh`。写别处会报 `[sandbox: file access denied]` —— 这**不是**要你绕过去，而是需要你批准的一次性提权 |
| **`vite build` 会 spawn EPERM** | 沙箱禁止子进程管道。绕过法：`npx vite --configLoader native`（dev/build 都有效，实测 dev 可用）；`npm run dev` 在本沙箱不可用，**与 `package.json` 无关，别去找它** |
| **无头浏览器起不来** | Edge 在沙箱下会因 mojo 命名管道被拒而崩。所以**页面视觉、浏览器端交互无法验证** —— 只能靠 HTTP 实测 + ESLint + 构建，并如实告诉用户"这部分我没验" |
| **Node 里 `child_process` 取管道输出会 EPERM**（连 `mysql.exe` 都不行） | 验证脚本**只做 HTTP**；"造临时账号 / 查库取证"放到 **pwsh** 里做 |
| **`.java` 是 CRLF 换行** | 自己写 Node 脚本做精确替换时，`old` 里写 `\n` **匹配不上**。做法：读入后 `replace(/\r\n/g,'\n')` 归一，写回再还原（`edit` 工具有时会匹配不上含 Java 转义引号 `\"` 的行，那种也用 Node） |
| **写 `.java` 别带 BOM** | `Set-Content -Encoding UTF8` 会带 BOM，`java` 单文件模式直接报 `非法字符: '\ufeff'` ⇒ 用 `[System.IO.File]::WriteAllText(path, text, (New-Object System.Text.UTF8Encoding($false)))` |
| **PowerShell 的 `>` / `Set-Content` 会改编码** | 生成给别的程序吃的文件（`.sql` 等）用 `cmd /c "... > file"` 或 Node 的 `writeFileSync`。BOM 会让 `mysql < init.sql` 直接语法报错 |
| **MySQL 中文** | `mysql.exe` 加 `--default-character-set=utf8mb4`，并在 pwsh 里设 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` |
| **MyBatis 会静默不赋值** | 项目开了 `map-underscore-to-camel-case`：字段名不匹配时**不报错、不警告**，只是那一个属性恒为 null（实测把 `create_time` 写成 `createdTime`，编译/单测/200 全过，只有那个字段空）。⇒ **新加实体/映射后，用真实数据打一次接口并检查每个字段都有值**，别只看状态码 |
| **`@Valid` 在进入方法体之前执行** | 想在 Controller 里 `trim` 后再校验是做不到的。要么改 DTO 正则（例如用 `^\s*$` 放行"用户以为删干净了"的空白输入），要么写自定义约束注解 |
| **改第三方库相关行为前先读它的源码** | 例：`vue3-slide-verify` 的硬校验区间与 `verify()` 成功条件 —— 只看现象（NaN）并按单次观测外推比例，会定位错方向 |

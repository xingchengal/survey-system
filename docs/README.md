# 项目文档（随仓库入库）

本目录只放**对读者与接手者有价值、且被代码注释直接引用**的文档。
四份主文档按职责分层，**不要互相复制数字或结论**。

## 一、主文档

| 文件 | 职责 | 什么时候读 / 更新 |
|---|---|---|
| [`../SPRINT.md`](../SPRINT.md) | 当前待办、未决项、明确不做 | **每次开工先读**；每轮收工只更新这里的状态 |
| [`ARCHITECTURE.md`](ARCHITECTURE.md) | 架构铁律、唯一口径、关键不变量、环境坑 | 改动权限 / 事务 / 缓存 / 状态机 / 上限之前按需读；仅在铁律变化时改 |
| [`AUDIT.md`](AUDIT.md) | 事实矩阵：端点四档、表、测试、页面、审计命令 | 动端点或表之前查；数量变化时同步，并跑审计命令核对四处一致 |
| [`HISTORY.md`](HISTORY.md) | 历史归档：轮次索引、决策、复盘、回滚 | **日常默认不读**；仅在复杂 Bug 排查 / 核心重构 / 追溯设计时按关键词检索 |

### 读取与写入规则

- 默认顺序：`SPRINT.md` → `ARCHITECTURE.md`（相关章节）→ `AUDIT.md`（相关矩阵）。
- `HISTORY.md` **不是现状依据**：其中数字、路径、行为以代码与 `AUDIT.md` 为准。
- 过程叙事（第几轮、改造前、踩坑经过）只进 `HISTORY.md`，**不写回代码注释**与 `ARCHITECTURE.md`。
- 数字口径以 `AUDIT.md` 为唯一出处；`README.md`、`ARCHITECTURE.md`、`SPRINT.md` 不重复写具体端点 / 表数。
- 改完文档或端点后跑 **`node tools/check-docs.mjs`**：端点计数、§四权限点、相对链接、README 规模、历史叙事泄漏必须全绿；CI 的 `docs` 作业会复跑。
- **提交**：日常可频繁小步 commit 便于回退；**push 前**用 `git rebase -i` / `squash` 整合成 Conventional Commits 格式的高质量 commit，并跑绿测试与检查（详见工作区 `AGENTS.md` 的「提交规范」）。
- 完整规则见工作区 `AGENTS.md` 的「问卷系统文档分层」。
